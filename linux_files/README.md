# Работа с файлами и каталогами Linux

## Задание

Повторить команды из презентации «Работа с файлами», показать примеры выполнения и разместить результат на GitHub.

## Выполненная работа

- [commands.sh](commands.sh) — последовательность команд по слайдам 3–18.
- [execution.txt](execution.txt) — фактический вывод выполнения команд в Linux, включая запросы подтверждения и результаты поиска.
- [interactive_demo.py](interactive_demo.py) — воспроизводимая проверка интерактивных команд в псевдотерминале.

Все примеры выполнены в учебной среде Linux с Bash. Основной сценарий завершился с кодом 0; интерактивные примеры также прошли успешно. Нажатия клавиш в интерактивных примерах передавались автоматически. Из журналов удалены только управляющие последовательности оформления терминала. Время, имя пользователя, размеры каталогов и временные пути зависят от среды запуска.

## Краткие пояснения и примеры

### Типы файлов и список каталога

Первый символ в `ls -l`: `-` — обычный файл, `d` — каталог, `l` — символическая ссылка, `s` — сокет, `p` — именованный канал FIFO. Сокеты Unix и FIFO позволяют процессам обмениваться данными; сокет Unix не следует путать с сетевым TCP-соединением.

В `ls -F` к имени добавляется `/` для каталога, `*` для исполняемого файла, `@` для символической ссылки, `|` для FIFO, `=` для сокета. Для демонстрации дополнительно использованы `chmod +x`, `ln -s` и `mkfifo`.

В строке `ls -l` последовательно показаны тип и права, число жёстких ссылок, владелец, группа, размер, дата изменения и имя. Права `750` означают `rwx` для владельца, `r-x` для группы и отсутствие прав для остальных.

### Создание и удаление каталогов

```bash
mkdir -p nested/level2/level3
mkdir -m 750 private
mkdir -p removable/child/leaf
rmdir -p removable/child/leaf
```

`mkdir -p` создаёт недостающие родительские каталоги. `rmdir -p` удаляет пустой конечный каталог и его пустых родителей. Для непустого каталога применяется `rm -r`. `-i` запрашивает подтверждение, `-v` показывает удалённые объекты.

### Редактирование

В `ed` выполнены замена второй строки, сохранение и выход:

```text
$ ed notes.txt
2c
Hello from ed!
.
w
q
$ cat notes.txt
Linux file commands
Hello from ed!
```

В `vi` выполнена последовательность `i` → ввод `Hello from vi!` → `Esc` → `ZZ`. Затем файл открыт повторно, внесено несохранённое изменение, выполнен выход `Esc` → `:q!` → `Enter`. Проверка показала, что в файле сохранилась только исходная строка:

```text
$ cat vi_notes.txt
Hello from vi!
```

`ZZ` вводится двумя заглавными Z в командном режиме. Для создания файла через `cat > cat_notes.txt` после ввода строки нажаты `Enter` и `Ctrl+D`.

### Просмотр текста

`cat notes.txt file1.txt` последовательно выводит содержимое двух файлов. `more long.txt` открывает постраничный просмотр. Проверены пробел (следующая страница), `Enter` (одна строка), `b` (предыдущая страница) и `q` (выход).

Дополнительные сочетания из презентации: `h` открывает справку `more`, `Ctrl+C` прерывает программу. `Ctrl+S` при включённом управлении потоком терминала приостанавливает вывод, `Ctrl+Q` возобновляет его. Это управление терминалом, а не отдельные команды `cat`.

### Копирование и перемещение

```bash
cp notes.txt notes_copy.txt
mkdir copies
cp notes.txt notes_copy.txt copies
cp -i notes.txt copies
mkdir backup
cp -r copies backup
mv notes_copy.txt renamed.txt
mv renamed.txt copies
mv copies katalog
mkdir destination
mv katalog destination
```

На запрос `cp -i` дан ответ `n`: существующий файл оставлен без изменений. В сценарии этот ожидаемый отказ обработан отдельно. При проверке `rm -i file?` дан ответ `y` для `fileA` и `n` для `fileB`; после этого `ls fileB` подтвердил сохранение второго файла.

### Выборка столбцов

В подготовленном `tabl1` город начинается с позиции 15:

```text
1 Ivan   578   moscow
2 Peter  435   newyork
3 Sasha  734   orel
```

```text
$ cut -c 1,3,4,5,15-21 tabl1
1Ivamoscow
2Petnewyork
3Sasorel
```

Позиции считаются с 1. Список позиций передаётся одним аргументом, без пробелов после запятых.

### Поиск строк

```text
$ grep -ci "Red Hat Linux" docs.txt
2
$ grep -E "get|put|print|write" docs.txt
get data
put data
print result
write file
$ grep '^a.*z$' docs.txt
applez
abz
$ grep '^[aA]$' docs.txt
a
A
$ grep '\$1\.00' price
Tea: $1.00
```

`-c` считает подходящие строки, `-v` выбирает неподходящие, `-i` игнорирует регистр. Точка обозначает один произвольный символ; `*` — ноль или больше повторов предыдущего элемента; `.*` — произвольную последовательность. `^` и `$` обозначают начало и конец строки. В последнем примере доллар и точка экранированы, чтобы искать их буквально.

### Поиск файлов

```bash
find search -name '*.c'
find search -type f -size +500
find search -type f -mtime -3
find search -type f -atime +3
find search -type f -user "$(id -un)"
find search -type f -group "$(id -gn)"
find search -maxdepth 1 -type f
find search -type f -atime +30 -exec rm -v {} \;
```

Поиск `*.c` нашёл `search/main.c` и `search/subdir/util.c`. По размеру найден файл `search/big.bin` размером 300000 байт. Без суффикса `-size` использует блоки по 512 байт с округлением вверх; `+500` означает больше 500 таких блоков.

Для проверки времени создан учебный `old.txt`, которому командой `touch -a -m -d "40 days ago"` установлены старые времена доступа и изменения. `-mtime -3` выбирает недавно изменённые файлы, `-atime +3` — файлы с достаточно старым временем доступа. Возраст для этих условий считается в полных 24-часовых периодах; `+3` означает больше трёх полных периодов. Условие `-atime +30` выбрало только учебный старый файл:

```text
removed 'search/old.txt'
```

`{}` заменяется найденным путём, `\;` завершает команду `-exec`. Все примеры удаления ограничены созданной учебной папкой. Абсолютные пути из слайдов заменены доступными учебными путями.

## Исправления неточностей презентации

1. В командах используется обычный дефис `-`, а не типографское тире `–`, и латинские буквы в `cat`, `cut`.
2. У `mv` нет ключа `-r`: каталог перемещается обычным `mv каталог назначение`.
3. Для альтернатив `get|put|print|write` нужен `grep -E` либо `egrep`. `egrep` показан по условию; для новых команд предпочтителен `grep -E`.
4. В `cut` нельзя разделять список позиций неэкранированными пробелами. Диапазон выбирается по фактическому расположению данных.
5. `touch *.txt` обновляет время существующих файлов `.txt`. Поэтому перед примером созданы `file1.txt` и `file2.txt`. В обычном Bash без совпадений шаблон может превратиться в буквальное имя `*.txt`.
6. `ed` и `vi` — отдельные программы, а не встроенные команды shell.
7. Вместо `bashes` обычно имеется в виду `.bashrc`. Bash в режиме login читает `/etc/profile` и первый доступный из `~/.bash_profile`, `~/.bash_login`, `~/.profile`; интерактивный non-login Bash читает `~/.bashrc`. Это не два файла, которые обязательно запускаются при каждом сеансе.
8. Корректная запись условия поиска — `-atime +30`, с пробелом между ключом и значением.

## Как повторить

В Linux с Bash, GNU coreutils, findutils, grep, `man`, `ed`, `vi` и `more`:

```bash
bash commands.sh > my_execution.txt 2>&1
```

Сценарий создаёт новую папку через `mktemp -d` и сообщает её путь в конце. При повторном запуске используется новая папка. Для независимого повтора автоматизированных интерактивных примеров нужны Python 3 и модуль `pexpect`:

```bash
python3 interactive_demo.py > my_interactive_execution.txt
```

Можно также повторить действия редакторов вручную по описанию выше. Для подготовки решения использовался ChatGPT.
